# Приёмка независимой реализации

Эти траектории позволяют сравнить две реализации в одинаковых условиях. Они дополняют сценарии шести разделов OpenSpec. Файл [gesture-vectors.json](gesture-vectors.json) содержит входы и наблюдаемые результаты. Другой проект может использовать собственный формат модели, движок анимаций и библиотеку событий.

## Проведение проверки

1. Создать из `initial` новую сцену для каждого случая. Камеры различать по идентификаторам. Отключить системное уменьшение движения, кроме примеров с `reduced: true`. Время между событиями считать нулевым, часы автоповтора продвигать только командой `wait`.
2. Для каждой тройки `[событие, аргумент, ожидаемые поля]` передать событие обычным входам своего редактора. После обработки считать независимо полученное состояние, включая видимый предпросмотр. Для `up` сначала снять результат и параметры начавшейся анимации, затем дождаться удаления копии и проверить, что следующая операция доступна.
3. Записать JSON вида `{"version":1,"observations":{"camera-swap":[{"lift":false},{"lift":true,"target":1,"order":"ABCD"},{"order":"BACD","landing":190,"undo":1}], …}}`. Ключи — все идентификаторы из файла. Элементы массива соответствуют шагам по порядку. Дополнительные наблюдаемые поля допустимы. Значения берутся из редактора.
4. Из корня распакованного пакета выполнить `node openspec/acceptance/check.mjs путь/к/observations.json`. Требуется Node.js с поддержкой ES-модулей, сторонние зависимости отсутствуют. Пропуск случая, шага или поля и расхождение значений дают ненулевой код выхода.

## Условные обозначения

- `cells` — одна строка или один столбец, слева направо или сверху вниз. Каждая буква обозначает отдельную камеру, подчёркивание — пустую позицию. `rows` перечисляет строки сверху вниз, включая содержимое под объединением. `picked` — исходные индексы с нуля. `rect`, `neighbor` — [лево, верх, ширина, высота] в шагах; у примеров с объединением основная камера первоначально в левом верхнем углу. `at` — активный адрес. `size` — ширина и высота. Стороны `n/e/s/w` — верх, право, низ и лево.
- Для `move`, `move-area`, `strip`, `resize`, `remove`, `ring` и `outer-cell` исходный захват уже начат. Для обычного переноса он в центре первой выбранной ячейки, для полос — в центре заголовка `grip`. `move` передаёт **полное** смещение от начала текущего захвата, а не приращение. Положительное направление у камеры — вправо и вниз. У `strip` смещение задано одной координатой вдоль выбранной оси. У `remove` это пара [вдоль, поперёк] в CSS-пикселях. При `insert` считать `down` нажатием на плюс у стыка `seam`.
- Для `resize` изменяется указанный угол, `pitch` задаёт размер шага в пикселях. У `ring` и `outer-cell` компоненты [X,Y] положительны **наружу** по захваченным осям. У камеры начало этих примеров прямо на краю стены. `room` — доступное расстояние по каждой оси. `wait` — миллисекунды с предыдущего события, `cancel` — Escape.
- Для проверки модели `move-area.move` указывает смещение в целых шагах. `extent` задаёт размер в позициях при закреплённом верхнем левом угле, `bounds` задаёт прямоугольник полностью. `cutRight` и `openRight` обозначают завершённый жест правой рамки на указанное число полос, `insertBefore` — щелчок по соответствующему плюсу, `clearAt` — щелчок по крестику. `toggle` означает Ctrl/Cmd-щелчок, `range` — Shift-щелчок, `click` — одиночный обычный щелчок. Для `clear.down/up` индекс означает кнопку соответствующей ячейки, null на отпускании — указатель вне кнопки.
- `order` и `rows` — зафиксированное содержимое; `preview` — возможный порядок после вставки/удаления; `forecast` и `returnForecast` — соответствия «освободившаяся позиция → камера». Индексы в одномерных примерах начинаются с нуля, адреса в двумерных с A1. `lift` — поднятая копия, `start` — начало блока полос в пикселях, `target` — цель одиночного обмена, `shift` — смещение набора в позициях, `seam` — стык с нуля. null означает отсутствие видимой цели. `selection` — текущий набор.
- `live` — непрерывный размер изображения, `snap` — пунктирный, `size` во время жеста рамки — показанный будущий размер, после отпускания — принятый. `returning` и `absorbed` перечисляются для сравнения по строкам. `invalid` — запрещённая цель. `undo` — число доступных отмен от чистой сцены. `landing` и `settle` — длительность запущенной посадки копии и доводки кадра в миллисекундах, 0 означает отсутствие соответствующей анимации.

Приёмку на живом видео дополняют проверкой наложений, границ и доступности из [основного описания](../README.md). Траектории фиксируют решения в точках, где расхождение влияет на результат жеста.
Для shared-divider задана уже зажатая боковая ручка (A2.e — правая у A2). move задаёт полный ход в пикселях. widthsPx — видимые ширины кадров по строкам, округлённые до пикселя; absorb — видимость прогноза поглощения, rightSpringA2 — правое смещение A2 в долях ширины стены, округлённое до шести десятичных знаков.

В сценариях `resize` пошаговый режим на внутренней ручке выбирается с Alt. Для `shared-corner` угол уже зажат обычной кнопкой мыши. `move` задаёт смещение от нажатия в CSS-пикселях, `sizesPx` перечисляет размеры C1, D1, C2 и D2 в этом порядке.
Значение null в sizesPx означает, что камера этой позиции поглощена и отдельного кадра на стене нет.

В multi-divider ручка C1.s зажата до первого события. move задаёт полный ход вниз от нажатия в CSS-пикселях. heightC1 — видимая высота C1; visibleC2 и visibleC3 — наличие отдельных кадров этих камер в сетке.
