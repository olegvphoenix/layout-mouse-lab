# Спецификация редактора раскладок

Этот пакет описывает поведение редактора для реализации в другом проекте. Источник требований — шесть файлов `specs/*/spec.md`. Сценарии GIVEN / WHEN / THEN задают ожидаемое поведение. [Приёмка в другом проекте](acceptance/README.md) содержит 40 машиночитаемых траекторий и команду для сравнения наблюдений вашей реализации. Тестовый HTML нужен для сравнения поведения. Спецификация не зависит от его DOM, обработчиков, браузера, Git-репозитория или сервера.

## Как читать координаты и результаты

Ширина × высота означает столбцы × строки. A1 находится вверху слева. Адрес относится к месту в сетке, камера может его менять. Числа 4, 5 и ±2 в сценариях перетаскивания указаны в CSS-пикселях. Порог подъёма измеряется от места нажатия, запас привязки границы — от середины шага отдельно по каждой оси.

При очистке пропадает содержимое видимой ячейки. При уменьшении объединения возвращаются его сохранённые части. Удаление внутренней полосы меняет адреса и состав, отмена восстанавливает её. Сжатие внешней рамки временно скрывает край, а его повторное расширение может вернуть прежние камеры. Для каждого из этих действий нужен отдельный тест.

## Проверка движения

| Фаза | Что видно и что проверять |
| --- | --- |
| Нажатие и начало движения | Порог центра ячейки 4 px, заголовка полосы 5 px. Уже при нажатии на внешнюю ручку горят одна или две линии. |
| Перенос | Кадры следуют за мышью в натуральном размере. Для ячеек след похож на пустую позицию, для полос заштрихован. Неподнятые кадры сохраняют исходные позиции до сброса. |
| Изменение размера | Живая граница следует за мышью, выбранные шаги показывает пунктир. Дрожание, возврат одной оси и полный возврат проверяются до отпускания. |
| Отпускание | Допустимый перенос сразу меняет модель, копия приземляется за 190 мс. Доводка кадра при внутреннем изменении размера занимает 120 мс. Новый захват доступен сразу. |
| Отмена и уменьшенное движение | Возврат в исходную позицию, выход и Esc проверяются отдельно для каждого жеста. При системном уменьшении движения сохраняются обратная связь и итог, пропускаются посадка и доводка. |

## Граница переноса в продукт

Пресеты, сброс демосцены, имена «Вход 01» и «Мост 03», изображения камер, URL примеров и локальная история вкладки — средства воспроизведения сценариев. В продукте проверки начинаются с эквивалентной раскладки принимающего приложения. Интеграция связывает результат операции с его существующими камерами, правами, хранилищем и механизмом сохранения. Этот пакет не задаёт формат API и срок хранения скрытого содержимого между рабочими сессиями.

Цель паритета с толстым UI шире проверенной механики. Отдельного решения при интеграции требуют параметры реальных видеопотоков, карты и панели, перенос устройств из дерева, FrameMerge, связи камер с информационными и тревожными панелями и обмен сохранёнными раскладками между клиентами. В исследовании также рассматривались плавная перестройка пропорций общей границы и рост сетки при сбросе центра камеры за край. Общая внутренняя сторона позволяет зафиксировать дробную пропорцию. На внутреннем шве боковая ручка задаёт пропорцию и переходит к фиксации при сужении соседа ниже 80 px. На внешнем крае ручки управляют ростом. Исследовательские сравнения Nx Witness и FancyZones не добавляют команд в продукт.

## Внедрение в WebClient

Целевые модели — текущий WebClient и настольный Axxon. В текущем WebClient ограничено интерактивное расширение до 16 позиций по оси. В изученном пути ручного расширения настольного Axxon такого предела нет; протокол хранит коллекцию ячеек. В макете по умолчанию можно исследовать сетки за 16. Для воспроизведения действующего ограничения WebClient служит параметр profile=webclient. Дробная настройка шва не увеличивает число позиций ни в одном профиле.

Контракт платформы уже передаёт right_spring и bottom_spring для ячейки. Для внедрения WebClient должен читать оба поля, учитывать их при вычислении экранных прямоугольников, захвате мышью и выводе видео, сохранять через существующую операцию обновления раскладки. Базовую геометрию и топологию соседей следует рассчитывать отдельно. Прототип проверяет представимость экранных прямоугольников через эти поля; сохранение в рабочий сервер и повторное открытие в обоих клиентах входят в приёмку интеграции.

В настольном Axxon при сужении ниже 80 пикселей обработчик может перейти к операции фиксации камеры. В макете основной жест боковой ручки повторяет этот переход; до отпускания можно вернуться к дробной пропорции. В изученном Nx закреплённые элементы используют целую сетку, незакреплённые — также дробную поправку отдельного элемента. Для общей границы двух соседей принимается модель Axxon.
